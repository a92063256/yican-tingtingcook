本目录及 `public/images/howtocook-*.webp` 由已复核的 `howtocook-bundle-v1.zip` 提取，供服务启动时离线导入，不重复纳入原 ZIP。

| 路径 | 内容 |
| --- | --- |
| `manifest.json` | 原包清单原始字节，包括菜谱路径、Markdown 校验值、图片对应关系、来源及许可说明 |
| `source/dishes/` | 369 篇原始 Markdown，保留上游字节用于 SHA-256 校验 |
| `licenses/HowToCook-LICENSE` | 原包随附的 HowToCook Unlicense 原文 |
| `bundle.json` | 原 ZIP、清单和许可的校验值及资源数量 |
| `cover-review.json` | 过程图和待核对图片的复核结论，关联原 ZIP 校验值 |
| `cover-corrections.json` | 逐菜谱的移除、替换、保留结论，以及替换图的来源、许可、上游 Git Blob 和本地 SHA-256 |
| `../../public/images/howtocook-<SHA-256>.webp` | 按完整内容哈希去重的图片，多个菜谱可共享同一文件 |

清单里的图片文件名保留原包路径，运行时按图片 SHA-256 定位去重文件。原包图片保留供追溯及兼容用户已有封面；过程图与明显错配的借图不再作为对应菜谱封面显示。2026-10-22 另外从同一固定上游提交下载并逐张确认 25 张成品照，缩小为最长边 960 px 的 WebP，共 1,665,280 字节。替换图同样按内容哈希去重，由修正记录覆盖原清单对应关系，不修改原清单或原文。全部图片与生成插画保留其来源许可，不统一改为项目 AGPL 许可。

当前 369 道菜谱中，173 道显示同菜成品原图、11 道显示较接近的参考照片、11 道保留原包生成插画、2 道原包照片尚待确认、172 道使用中性「实拍待补充」占位。详见 [封面复核记录](../../docs/菜谱封面复核记录.md)。缺图不再使用别的主料或菜型凑图。

维护者在仓库根目录执行 `python scripts/prepare-howtocook-bundle.py "原ZIP路径"` 可重建本次 v1 资源。脚本仅依赖 Python 标准库，校验资源后写入，不执行包内代码。封面复核记录另行维护，更新包需要重新复核并调整脚本数量约束，不能沿用其他包的校验值。

用户运行应用只需项目规定的 Node.js 24+ 和依赖，不需要 Python、原 ZIP 或网络下载。启动时校验清单、许可、每篇 Markdown、去重图片及替换图，资源不完整则停止启动。修正记录计入内容版本；已有公共导入和带继承标记的私家版本会更新受管理封面，不覆盖用户自选封面、菜名、食材或步骤。有业务数据的文件库更新前自动备份。不要修改原始文件或转换其换行；需要调整做法时通过应用另存自家版本。

初始化与标注规则见 [HowToCook 导入说明](../../docs/HowToCook导入说明.md)。
