# 厨房管理与菜谱编辑

## 操作入口

- 右上角账号 → 厨房与成员管理；手机也可从「我的 → 厨房与成员管理」进入。
- 主厨从「我的 → 管理自家菜单」进入菜单，点击菜品铅笔编辑；「我的 → 发现菜谱」可将公共菜谱改成自家的做法。
- 账号面板中的退出账号仅结束当前登录；管理面板中的退出厨房才会结束厨房成员身份。

## 厨房权限与生命周期

| 操作 | 执行者 | 结果 |
| --- | --- | --- |
| 退出厨房 | 长期客人、仍有效的单餐客人 | 结束本厨房长期成员与所有单餐授权，失去本厨房历史访问权限 |
| 移除成员 | 主厨或点菜主人 | 仅能移除客人；保留对方账号、其他厨房及历史订单、评价 |
| 交接身份 | 对应身份的主人本人 | 将自己的主厨或点菜主人身份交给一位长期客人；原主人变为客人，可随后退出 |
| 撤销邀请 | 两位主人 | 链接停止接受新加入；已加入的成员不受影响 |
| 解散厨房 | 两位主人 | 输入完整厨房名称并再次确认，封存厨房，所有成员停止访问，全部邀请及单餐授权失效 |

主人不能直接退出或互相移除，先交接可避免留下无主厨房。交接候选人不能是自己、另一位主人、单餐客人或其他厨房成员。交接立即在数据库事务中更新身份与权限，不需要重新登录；其他设备在下次同步后更新界面。

退出、移除后不删除原订单或评价，厨房中的其他成员仍可查看历史。有效邀请可以用于再次加入，因此需要阻止旧链接再次使用时，还应撤销邀请。撤销邀请不能代替移除成员。

解散采用 `Kitchen.archived` 封存，邀请采用 `Invite.revoked`。兼容现有关系型存储的扩展字段，无需清库。封存后的厨房不出现在授权视图中，点菜、评价及管理命令也会拒绝；原始数据留在本机数据库。当前不提供厨房恢复界面或物理清除功能。

## 菜谱编辑

主厨可编辑菜名、自定义分类、参考人数、预计分钟、介绍、封面、食材名称／数量／单位／类型、做法步骤与来源链接。食材按行增删，步骤可增删和上下移动，人数与时长未知可留空，食材数量为空表示待确认或适量。

封面可保留原有导入图片，或选择内置菜品插画；本次未增加本地照片上传和裁剪。导入的原始教程 `sourceText` 随新版本保留，避免用简化做法覆盖完整来源。

保存创建厨房自己的菜谱版本，替换当前菜单引用，保留旧版订单、备菜计算和评价关联；不改其他厨房和公共菜谱。编辑器记录打开时的菜谱与菜单快照，发生并发修改时拒绝覆盖，提示重新打开。

「从自家菜单移除」需确认，只影响后续选菜，不删除原菜谱版本或订单。发现页点击已加入菜谱的对号可直接移出当前菜单，恢复加号；公共菜谱仍可从发现页重新加入；被移除的私家版本当前没有专门的恢复入口。

## 验证与边界

自动验证使用独立数据库及 loopback 服务，不修改正式数据，不开放局域网。新增 10 项业务与持久化测试；完整 88 项测试、类型检查及生产构建通过。浏览器完成 28 项断言，覆盖二级入口、成员移除、邀请撤销、编辑保存与刷新、发现菜谱另存、菜单移除、交接后退出、输入名称解散；检查 320 / 360 / 390 / 1440 像素布局并查看截图，无横向溢出或运行时错误。

真实手机软键盘和 Wi-Fi 未验证：本次调试限定本机，桌面浏览器不能覆盖实机输入体验。最小手动步骤是在手机宽度打开「我的 → 管理自家菜单」，逐项编辑食材、滚动到底部再保存，预期输入可见、保存栏可触达，重开后属性保持。退出或解散仅在专门新建的测试厨房验证，避免影响实际成员；真实跨设备测试由用户决定后安排。

本次补齐厨房、成员、邀请和菜单的反向操作，未扩展账号删除、库存物理删除、餐次取消或评价删除等其他生命周期功能。
