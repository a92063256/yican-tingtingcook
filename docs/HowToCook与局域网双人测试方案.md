# HowToCook 与双人使用验证

本文按当前版本整理，所有账号、厨房名称、地址和路径均为示例。功能与运行方式以 [新手使用指南](新手使用指南.md)、[局域网使用说明](局域网使用说明.md) 为准。

## 当前实现

- 内置 369 道 HowToCook 菜谱及离线封面，服务启动时自动校验并导入。普通使用者无需下载上游源码、安装 Python 或部署 Docker。
- Vue 页面与 Node.js API 共用一个服务；账号、厨房、成员、订单、库存与评价保存到本机 SQLite。手机登录后按权限访问同一数据库。
- 支持注册、密码登录、主动开启的免密码登录，以及长期成员和单餐邀请。一个厨房最多有一位主厨和一位点菜主人，其余为客人。
- 主题按当前浏览器和网址保存，账号及厨房数据由服务端持久化；多个浏览器的主题可以不同。
- 菜谱数量、封面分类、来源和限制见 [HowToCook 导入说明](HowToCook导入说明.md) 与 [封面复核记录](菜谱封面复核记录.md)。复杂用量保留待确认，不把未知用量伪装成精确数据。

## 本机验证范围

开发与自动验证仅监听 `127.0.0.1`，使用独立测试数据库，不修改实际使用库、不放行防火墙、不注册自启。两份独立浏览器会话可以验证账号隔离与业务同步，但不能替代真实手机软键盘或 Wi-Fi 检查。

```sh
npm ci
npm test
npm run build
```

Windows x64 维护者可运行 `build-portable.cmd` 生成便携 ZIP，再运行 `npm run test:portable`。后者在独立目录中测试本机启动、注册、建厨房、库存持久化、备份和迁移，不开放局域网。

## 用户自行部署时的示例

以下仅说明用户明确选择局域网部署后的操作；开发调试无需运行局域网入口。推荐先阅读 [Windows 便携版说明](Windows便携版使用说明.md)。

1. 完整解压便携 ZIP，运行「点我启动到局域网.cmd」。电脑需要保持开机、服务运行。
2. 两台手机连接同一个普通 Wi-Fi，使用窗口打印的实际地址。
3. 第一位用户注册并创建「示例小厨」，选择主厨；发送长期邀请链接。
4. 第二位用户从邀请链接注册或登录，选择空缺的点菜主人身份；后续用户以客人身份加入。

```text
点菜手机 ─┐
          ├─ 同一 Wi-Fi ─ 电脑提供网页和 API ─ 本机 SQLite
主厨手机 ─┘
```

`http://192.168.1.23:3000` 仅为地址示例，不表示当前电脑地址。以启动窗口输出为准，IP 和端口可能变化；无需配置路由器端口映射或公网穿透。仅在确有必要时由使用者自行调整专用网络的防火墙。

## 最小人工验收

仅使用专门创建的测试厨房，避免影响实际成员和订单。

| 操作 | 预期结果 |
| --- | --- |
| 主厨开一顿未来餐次，点菜人选择菜品并提交 | 主厨在后续同步中看到同一份订单和备注 |
| 主厨修改份数或库存，另一端刷新 | 读取到服务端已确认的数据，不被另一客户端旧状态覆盖 |
| 输入「干辣椒 一斤，番茄 三个，五花肉两份」 | 预览完整三项；确认后保存为 1 斤、3 个、2 份 |
| 主厨在发现菜谱点击加号，再点对号 | 加入后可移出菜单、恢复加号；历史记录保留 |
| 发出邀请后撤销，或移除客人 | 撤销链接阻止新加入；移除成员结束其厨房访问权限 |
| 停服期间尝试保存 | 明确提示未确认，不假装成功；恢复后按界面提示重试 |
| 停止再启动电脑上的服务 | 登录后的厨房、菜单、库存及历史仍可访问 |
| 在账号设置修改密码 | 其他设备的旧会话失效，重新登录使用新密码 |

真实手机与 Wi-Fi 不在本机自动验证范围。是否进行实机测试由使用者决定；预期及注意事项见上表。PWA、图片识别、公网部署和开机自启尚无一键方案。
