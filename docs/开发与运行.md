# 开发与运行

面向想读代码、改代码、在本机跑开发环境的人。只想使用的话看[新手使用指南](新手使用指南.md)。

## 环境

- Node.js **24 LTS 或更新版本**。SQLite 使用 Node 内置的 `node:sqlite`，不需要安装数据库服务。
- 更新功能需要 Git。
- Windows 有现成的 `.cmd` 脚本；macOS 与 Linux 用命令行。

## 安装与启动

```sh
npm ci
npm run dev -- --port 5173
```

开发模式：API 监听 `127.0.0.1:3000`，页面在 `127.0.0.1:5173`，Vite 把 `/api` 代理到 API。页面热更新；改服务端文件需要重启。

Windows 双击 `start-demo.cmd` 等价于上面的命令。

## 三种启动方式

| 方式 | 命令 | 监听 | 用途 |
| --- | --- | --- | --- |
| 开发 | `npm run dev` / `start-demo.cmd` | `127.0.0.1` | 改代码、热更新 |
| 构建后本机运行 | `npm run build && npm start` | `127.0.0.1:3000` | 验证生产构建 |
| 局域网部署 | `start-lan.cmd` → `node scripts/entry.mjs start --host 0.0.0.0` | `0.0.0.0:3000` | 给同网设备使用 |

默认 `npm start` 只监听本机。开发调试不要运行部署脚本，也不要改防火墙。

## 命令

| 命令 | 作用 |
| --- | --- |
| `npm run dev` | 开发服务器（API + Vite） |
| `npm run build` | `vue-tsc` 类型检查 + Vite 生产构建 |
| `npm run package:portable` / `build-portable.cmd` | Windows x64 便携包，内置 Node 与对应源码 |
| `npm run test:portable` | 已生成便携 ZIP 的本机启动、备份与持久化检查 |

| `npm run backup` | SQLite 在线备份到 `data/backups/` |
| `npm run db:rehearse` | 数据库迁移演练（不写入） |
| `npm run db:migrate` | 应用迁移 |
| `npm run import:howtocook -- <目录>` | 旧版手动导入工具 |
| `npm run test:load` | 负载测试 |

## 部署器与版本目录

`start-lan.cmd` 最终调用 `node scripts/entry.mjs start --host 0.0.0.0`。入口只做版本选择，真正的逻辑在所选版本的 `scripts/deployment.mjs`：

```
项目根/
  .yican/
    current.json          当前激活的版本
    instance.json         运行实例与端口
    releases/<commit>-<hash>/  每次更新安装的完整版本
    pending-update.json   未完成的切换（用于失败恢复）
    recovery/             回滚时保留的失败现场
    logs/                 更新日志
```

`entry.mjs` 支持四个动作：

```
node scripts/entry.mjs start [--host 0.0.0.0] [--port 3000]
node scripts/entry.mjs update
node scripts/entry.mjs status
node scripts/entry.mjs stop
```

更新流程：拉取远程 → 备份数据库 → 在独立目录安装候选版本 → 用数据库副本演练 → 预检通过后停服、切换、恢复 → 失败回滚。控制通道带令牌，只在本机回环地址监听。

## 目录结构

```
src/          Vue 前端与领域逻辑
server/       HTTP 服务、账号、存储、迁移、备份
content/      内置 HowToCook 内容与清单
public/       静态资源（含按哈希去重的菜谱封面）
scripts/      开发与部署脚本
docs/         文档
data/         运行时数据库与备份（不入库）
dist/         构建产物（不入库）
release/      Windows 便携目录、ZIP 和 SHA-256（不入库）
build/        便携构建暂存、许可证缓存和隔离验证（不入库）
```

## 配置项

| 变量 | 默认 | 说明 |
| --- | --- | --- |
| `YICAN_HOST` | `127.0.0.1` | 监听地址；局域网需要 `0.0.0.0` |
| `YICAN_PORT` | `3000` | 端口 |
| `YICAN_DATA_DIR` | `<项目>/data` | 数据库目录 |

开发时想用独立数据库，只设 `YICAN_DATA_DIR` 即可。

## 数据

- 主库 `data/kitchen.sqlite`，运行时伴随 `-wal` / `-shm`。
- 备份必须走 `backup`（`node:sqlite` 的在线备份），**不要复制主文件**。
- 恢复：停服 → 保留原 `data` → 新建空目录 → 备份改名为 `kitchen.sqlite` → 启动，不混入旧 WAL/SHM。
- 同一数据库只允许一个服务实例。

## 内置内容维护

内置内容在 `content/howtocook`，图片在 `public/images/howtocook-<sha256>.webp`。启动时校验清单、许可、每篇 Markdown 与图片，资源不完整会中止启动。

重建 v1 资源（仅维护者需要）：

```powershell
python scripts/prepare-howtocook-bundle.py "原ZIP路径"
```

脚本只依赖 Python 标准库，校验后提取，不执行包内代码。替换封面时维护 `cover-corrections.json`，不要覆盖原始文件。

```sh

```

测试使用独立临时数据库。改动后至少跑一遍全量测试与构建。

## 反向代理注意事项

如果要把服务放到反向代理后面：

1. **必须保留 `Host` 头。** `server/http.ts` 用 `Origin.host !== Host` 做同源校验，Host 被改写后所有写操作返回 403。nginx 用 `proxy_set_header Host $host;`。
2. **客户端 IP 会失真。** `req.socket.remoteAddress` 在代理后恒为 `127.0.0.1`，按 IP 的登录/注册限流会变成全站共享桶。需要在服务端显式信任代理并读取 `X-Forwarded-For`，只在可信代理下启用——**该支持尚未实现**。
3. **Cookie 的 `Secure` 依赖 `socket.encrypted`。** TLS 在代理终止时永远为 false，需要读取 `X-Forwarded-Proto` 后再设置——**同样尚未实现**。
4. **注册接口默认开放。** 公网暴露前应改为邀请制，否则会被批量注册。

## 已知限制

- 单实例、单数据库，不支持横向扩展。
- 没有邮箱、短信、找回密码。
- 没有 PWA / 离线缓存，没有图片上传识别。
- 没有 Docker 镜像与公网一键部署方案。
- 仅面向可信局域网，未做公网加固。
