# 主题与用餐日志

## 使用入口

- 手机：底部「我的 → 主题颜色」；桌面：「厨房设置 → 主题颜色」。轻点主题即刻应用，点「选好了」关闭。
- 手机：底部「日志」；桌面：左侧「用餐日志」。设置页也保留日志入口。
- 日志默认定位到最近一餐；左右箭头翻月，点击月份可直接选年月，「回到今天」定位到今天。点击日期查看当天全部餐次。

## 配色参考与实现

参考 Happy Hues 对背景、正文、主操作和辅助色的分工，结合现有温馨、克制留白的设计调整为五套浅色主题。以下是设计来源，不是逐个色值原样套用；深色案例也转换为适合菜单阅读的浅色表面，操作色加深以保证白色文字可读。

| 主题 | 风格 | 网络参考 |
| --- | --- | --- |
| 杏檐暖照 | 陶土橙、奶油白，延续原有暖色 | [Palette 11](https://www.happyhues.co/palettes/11)，参考奶油白 `#f9f4ef`、暖沙 `#eaddcf` 与暖色点缀 |
| 松风煮雪 | 松针绿、薄荷灰、浅金 | [Palette 10](https://www.happyhues.co/palettes/10)，参考 `#004643`、`#abd1c6`、`#f9bc60` |
| 雾海听潮 | 雾蓝、浅沙 | [Palette 14](https://www.happyhues.co/palettes/14)，参考青白 `#e3f6f5`、浅青 `#bae8e8` 与暖黄点缀 |
| 暮山烟紫 | 烟紫、月白 | [Palette 6](https://www.happyhues.co/palettes/6)，参考紫 `#6246ea`、浅紫 `#d1d1e9` |

`src/themes.ts` 保存配色，`src/themes.css` 用语义变量统一页面、按钮、分类、月历、购物车、评价及设置弹层。菜品插画、成员头像与库存成功／缺货等状态保留各自含义。主题同时更新浏览器的 `theme-color`。

外观属于当前浏览器，不修改厨房共享数据，也不会改变饭搭子的选择。正常使用与 `?qa=1` 分别使用 `yican-theme`、`yican-theme-qa`；无效存储值回退到杏檐暖照。存储受限时仍可换色，并提示关闭后可能无法保留。

## 日志规则

- 日志面向厨房长期成员，只显示当前厨房。临时来客不展示整间厨房的历史。
- 有非零份数的点菜菜单，且主厨已标记完成或餐次结束时间已到，才计入日志。未来待用餐、空菜单、全部零份、取消餐次均不计入。
- 实心点表示主厨已完成；空心点表示餐次时间已结束，但尚未标记完成。历史点菜不被自动认定为实际完成用餐。
- 按餐次所属日期归档；跨午夜餐次等待结束时间到达，仍归入开餐日期。
- 一天可显示午餐、晚餐和自定义餐次。多人点同一道菜在同餐只计一道，实际份数以主厨设置为准。月度菜数按每餐累加，同一道菜跨餐出现会分别计算。
- 菜名、食材、步骤引用订单中的历史菜谱版本；不会用菜单中后来编辑的版本覆盖。菜单详情同时显示份数、点菜留言和已有评价，可进入原有餐后评价流程。
- 日志只读汇总现有状态，不新建数据库表，不写入餐次或订单，不自动完成餐次，也不扣减库存。

## 本机开发与验证

`npm run dev`、`npm run preview`、`npm start` 默认只监听 `127.0.0.1`。共享后端需 Node.js 24+。仅显式使用 `start-lan.cmd` 时才开启局域网；本轮开发和测试未运行该脚本，也未更改防火墙。

本轮验证：

- 55 项 Vitest 测试全部通过；新增 5 项日志业务测试涵盖生命周期、厨房权限、跨月统计、历史版本、缺失菜谱容错、跨午夜与只读性。
- TypeScript 检查与生产构建通过。
- Playwright 在独立 SQLite 测试库、仅本机服务上完成 51 项界面断言：五套配色、刷新保存、独立浏览器偏好、跨月、回到今天、空日期、历史菜谱、正确餐次评价和厨房切换隔离。
- 检查 320 / 360 / 390 像素手机布局与 1440 像素桌面布局，无页面横向溢出；主题弹层在视口内，内容独立滚动、底部按钮固定。没有浏览器运行错误。

未验证真实 iOS / Android 浏览器与真实用户数据库：本轮按要求不开放局域网，测试仅使用独立数据。最小手动核对：在电脑浏览器手机模式下切换任一主题后刷新，应保留选择；进入日志，选择有标记的日期，应出现对应菜单，点击菜品应打开当时版本。没有历史数据时显示空状态；若需真机检查，可使用手机本机运行的服务或 USB 转发，继续保持不向局域网开放。
