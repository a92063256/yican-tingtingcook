# HowToCook 菜谱与离线初始化

## 默认使用流程

项目随源码提供 369 道菜谱及本地封面。正常执行 `npm run dev` 或构建后执行 `npm start` 时，服务在接受请求前校验内容、初始化公共菜谱。普通用户无需原 ZIP、Python 或手工导入，也不会联网下载菜谱和封面。

- 新数据库只载入公共菜谱，不创建测试厨房、账号、订单或库存。
- 已有数据库补充缺少的公共菜谱，并给已识别的旧版 HowToCook 导入补充来源和默认封面。封面复核修正会更新原包受管理封面及带继承标记的私家封面；用户自选封面、菜名、食材、步骤、订单和评价保留。已有菜单不自动加入全部菜品，主厨从「发现菜谱」自行挑选。
- 对包含厨房、订单或私家菜谱的文件数据库，首次安装当前内置内容前，在数据库同级 `backups` 目录创建 `pre-bundled-catalog-*.sqlite` 一致性备份。
- 数据库保存内容版本标记，重复启动不重复写入。资源缺失或校验失败则中止启动，请恢复完整项目文件后重试，不要删除使用中的数据库。

默认数据库为 `data/kitchen.sqlite`，可用 `YICAN_DATA_DIR` 指定其他目录。初始化入口为 `server/index.ts`，规则在 `server/bundled-catalog.ts`；其他维护工具直接构造 Store 时不触发此导入。

## 来源、封面与显示

菜谱来自 [Anduin2017/HowToCook](https://github.com/Anduin2017/HowToCook)，固定提交为 `2b19c9e9ee926fd925a68207a57582a338813f9c`。原始 Markdown、清单、校验信息和许可保存在 `content/howtocook`，详见该目录 README。源菜谱随附 Unlicense，图片保留各自来源及许可字段，不由项目 AGPL 替换。

原包有 351 条封面配置，去重后为 170 个 WebP 文件，共 11,087,974 字节。封面复核另外下载 25 张上游成品照，共 1,665,280 字节，最长边不超过 960 px。图片由本机服务提供并按需加载，不依赖远程图片服务。

界面根据来源页、替代说明及逐菜谱复核结果判断匹配程度，不直接使用包内笼统的 `matched` 状态。当前为 173 道同菜原图、11 道较接近的参考照片、11 道生成插画、2 道待核对图片和 172 道中性占位。明显错配的借图、原料包装和备料过程图不作为成品封面；找不到适合成品图时显示「实拍待补充」。同菜原图以外的封面在图片左下统一显示「仅供参考」。逐项结论和来源见 [封面复核记录](菜谱封面复核记录.md)。

详情最末尾显示「菜谱来源于 HowToCook 开源库」及链接。来源归属与用户可编辑的参考链接分开保存，另存自家版本保留归属；更换封面清除旧图的精确匹配判定，历史及公共版本保留原封面。

食材用量采用规则解析：严格数字和单位可结构化，范围、近似值、公式和复杂备注保留待确认。原始教程以纯文本保留，不执行其中 HTML，不下载 Markdown 引用的远程图片；备菜前可查看原文，主厨可编辑成自家版本。包含调料和半成品分类。

## 维护内置内容

更新资源仅需维护者执行，普通用户不用运行：

```powershell
python scripts/prepare-howtocook-bundle.py "C:\path\howtocook-bundle-v1.zip"
```

脚本仅依赖 Python 标准库，校验清单、Markdown、图片和路径后提取，以图片 SHA-256 命名去重，不执行包内脚本。脚本针对本次 v1 包的数量约束，换成其他版本需同步调整约束，并重新复核封面、更新 `cover-review.json` 及测试。`.gitattributes` 保留上游文件原始字节，避免 Windows 换行转换导致校验失败。开发调试始终仅监听 `127.0.0.1`。

新的逐菜谱结论维护在 `cover-corrections.json`。替换图记录成品来源、许可、尺寸、字节数和 SHA-256，并随项目提交对应 WebP；不要覆盖原文件或使用远程热链。以后再次替换已修正图片时，将旧图片 SHA-256 追加到该菜谱的 `previousImages` 数组，使已有受管理封面能继续升级。初始化只识别该菜谱已知旧图，不按文件名前缀批量覆盖其他图片。

## 旧版手动导入工具

`npm run import:howtocook -- "C:\path\HowToCook"` 是从本地 HowToCook 源码目录预览导入的旧维护入口，不使用包内封面，也不等同于默认初始化。只有加 `--apply` 才写入数据库，运行前须自行执行 `npm run backup`。

该工具会替换测试目录、清理演示菜入口并向现有厨房菜单加入导入菜谱，不适合只想补充公共目录的日常用户。重复 ID 不新增重复条目，订单引用的版本及私家菜谱保留；报告和许可副本写入 `data/imports`。请先用 `YICAN_DATA_DIR` 指向独立数据库确认效果，再决定是否用于已有数据。`prune:categories` 同样属于手工维护工具，正常初始化不会执行分类清理。

## 验证范围与最小检查

封面修正后完整 110 项自动测试、TypeScript 与生产构建通过；本次隔离数据库浏览器完成 23 项断言，检查本地照片、占位、参考标识、私家保存，以及 320 / 390 / 1440 像素布局。浏览期间没有远程图片或菜谱请求。

未验证真实手机、软键盘和 Wi-Fi。最小检查：刷新本机页面，在「发现菜谱」搜索「梅菜扣肉」，预期看到扣肉成品照；搜索「咖喱炒蟹」，预期看到「实拍待补充」，不再是虾图；搜索「蒸水蛋」，预期看到蒸蛋参考图。打开详情后滚动到底部，应看到来源小字且无横向溢出。真实手机可用 USB 转发访问本机服务，继续保持仅监听本机，不为此运行局域网脚本或改防火墙。更多实机或网络验证由用户决定。
