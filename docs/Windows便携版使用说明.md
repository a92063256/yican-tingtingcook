# Windows 便携版

便携版适用于 Windows 10 / 11 x64。内置 Node.js 运行环境、网页、服务端和 369 道菜谱，使用者无需安装 Node、npm、Git 或数据库。首次启动和日常使用不需要连接外网。

## 启动

1. 把 `Yican-Windows-x64.zip` 完整解压到普通可写文件夹，例如 `D:\一餐\Yican`。不要在 ZIP 预览窗口中直接运行，不要放进 Program Files 等需要管理员写权限的目录。
2. 双击 `点我启动到局域网.cmd`，浏览器会自动打开。第一次打开后注册账号、创建厨房，再邀请家人加入。
3. 手机连接同一个 Wi-Fi，打开启动窗口中打印的局域网地址。保留启动窗口；电脑关机或服务停止后，手机将无法访问。

首次启动只初始化数据库和 369 道公共菜谱，不预置账号、厨房、成员、餐次、订单、库存或评价。注册账号后可以创建厨房，也可以通过邀请加入；创建厨房会从公共菜谱中默认选入 3 道起始菜单，主厨可自行增删和编辑。

若出现 Windows 防火墙询问，仅在自己信任的专用网络下允许访问。本程序不会自动修改防火墙或添加开机启动。

默认端口为 3000；被占用时会自动选择其他空闲端口，使用窗口中实际打印的地址。只想在本机使用，双击 `点我启动.cmd`，它只监听 `127.0.0.1`。

重复双击启动会打开已运行的服务。停止时按原窗口的 Ctrl+C，或者双击 `点我停止.cmd`。完整解压后的文件都需要保留，不要只移动启动脚本或 `node.exe`。

## 数据与备份

账号、厨房、库存和历史记录保存在便携目录下的 `data/kitchen.sqlite`，启动日志在 `.yican/logs/`。新发行的 ZIP 不包含任何用户数据、账号或预先初始化的厨房。

双击 `点我备份数据.cmd`，可在运行期间生成一致的 SQLite 备份，位置为 `data/backups/`。不要在服务运行时只复制数据库主文件，最近记录可能仍位于 WAL 文件中。

迁移到其他目录或电脑：先停止服务，再完整复制整个 `Yican` 目录。不要同时启动两份程序访问同一个数据目录。

主题颜色保存在当前浏览器的 `localStorage`，不写入账号数据库；刷新、正常关闭并重开浏览器后会恢复。同一浏览器访问同一网址时共享外观，切换账号也沿用；其他手机、浏览器、不同主机名或端口各自选择。清除网站数据或使用无痕模式后，偏好可能不会保留。

恢复备份：停止服务，把现有 `data` 目录改名保留；新建 `data` 文件夹，将备份文件改名为 `kitchen.sqlite` 放进去，再启动。不要混入旧 WAL/SHM 文件。

## 更新便携版

便携版无需 Git，不使用源码部署的 `一键更新.cmd`。

1. 双击 `点我备份数据.cmd` 并保留备份，然后停止旧版。
2. 把新版 ZIP 解压到另一个文件夹。
3. 将停止后的旧版 `data` 文件夹复制到新版 `Yican` 目录下，再启动新版；旧版目录暂时保留。

本次没有实现便携版自动下载、自动升级或开机自启。源码版的一键更新流程继续保留，见 `source/docs/一键更新说明.md`。

## 目录

```text
Yican/
  点我启动到局域网.cmd            局域网启动，自动打开本机网页
  点我启动.cmd      仅本机启动
  点我停止.cmd             停止本目录的服务
  点我备份数据.cmd           备份本目录的数据库
  launcher.mjs         便携启动管理器
  runtime/node.exe     内置运行环境
  app/                 网页、服务端、数据库结构和内置菜谱
  licenses/            Node、前后端依赖和 HowToCook 许可
  source/              此包对应的项目源码及构建脚本
  portable.json        项目版本、构建提交、运行环境与校验信息
  data/                首次启动后产生；更新时需要迁移
  .yican/              启动状态和日志
```

源码使用 AGPL-3.0-only，根目录 `LICENSE` 为完整协议。分发 ZIP 时保留 `source/`、`licenses/` 和所有运行资源。内置 HowToCook 内容继续使用其原许可。

## 维护者构建

维护者需要 Windows x64、Node.js 24+ 与 npm。在完整源码中双击根目录 `build-portable.cmd`，会安装锁定依赖、检查 TypeScript、构建网页、打包服务端和运行环境，并生成：

```text
release/Yican/                     可直接启动的目录
release/Yican-Windows-x64.zip      对外分发的 ZIP
release/Yican-Windows-x64.sha256   ZIP 的 SHA-256 校验值
```

也可以直接运行 `npm run package:portable`。构建器在独立临时目录安装依赖和构建，不重装当前源码目录的依赖。输出目录 `release/` 和暂存目录 `build/` 不提交到 Git；不要在 `release/Yican/` 里长期使用，先复制到其他目录。

构建默认内置执行构建命令的 Node 版本。仓库附带 v24.19.0 的完整官方许可证；其他版本首次构建通过 Node 官方 GitHub 仓库读取对应 LICENSE，缓存到 `build/`。网络不通时，可将该版本官方 LICENSE 保存到 `licenses/node-v版本号.txt` 后重试。

在 Git 工作区构建时，`source/` 收录被跟踪文件的当前内容，新增脚本需先 `git add`；未提交状态记录在 `portable.json`。发布前应提交源码后重新构建，以便追溯。便携包内的 `source/` 也可以直接双击 `build-portable.cmd` 重新构建，维护者仍需安装构建环境。

运行 `npm run test:portable` 会检查已生成的 ZIP：解压到独立的中文路径，使用不含 Node / npm / Git 的 PATH，仅在本机执行启动与数据持久化检查，不改动现有厨房数据库，不开放局域网。

## 常见问题

- **缺少 runtime/node.exe**：请完整解压 ZIP，不要只取启动脚本。
- **手机打不开**：确认用的是 `点我启动到局域网.cmd`、同一 Wi-Fi，并检查专用网络的防火墙权限；`点我启动.cmd` 本来就只允许本机访问。
- **无法创建数据库或日志**：换到当前用户可写的目录，不要直接在压缩包或只读介质中运行。
- **构建提示已有用户数据**：把整个 `release/Yican` 目录移到安全位置再构建；构建器不会清空它。

当前验证范围为本机 Windows x64 的独立目录和浏览器请求，不能代替另一台实体电脑或真实手机 Wi-Fi 验证。需要验证时，最小步骤是在另一台 Windows x64 电脑完整解压 ZIP，双击启动、注册并建厨房，随后在同一 Wi-Fi 的手机打开打印的地址；预期无需安装环境，手机可点菜，停止并重启后记录仍保留。开发调试仍只使用本机入口。
