# 账号与邀请设计

## 流程与身份

网页先查询 `/api/auth/me`，无会话显示登录／注册，有会话再获取可见厨房。邀请 ID 保存在 URL hash，认证后继续原邀请；退出邀请可回自己的厨房。公开邀请摘要仅含厨房名称、类型、有效期、餐次和主人名额，不含成员、订单或库存。

注册的主厨／点菜常用身份仅帮助预选，不直接授予权限。每个厨房一个 `chefId`、一个 `dinerOwnerId`，两者都是长期成员。主厨管理菜单、餐次、库存和备菜；两位主人共同管理名称、称谓和邀请。客人可以点菜、收藏、评价，不能管理厨房。

关系表保留 `memberships.role = chef | diner`，`diner` 表示可点菜成员，其中 `dinerOwnerId` 唯一指定点菜主人，其余是客人。`ownerId` 保留创建者历史含义，不再直接决定权限。`dinerOwnerId` 通过原有扩展字段持久保存，不重建旧表。长期邀请选择 `chef | diner | guest`，同一 SQLite 事务检查名额，竞争第二个主人会失败。

没有餐次时默认长期邀请。长期邀请 7 天有效；单餐邀请仅在开放且未截止时接受加入，餐后失去点菜权限。有本人订单且授权未撤销者保留对应历史，支持补评。

## 凭据与会话

新增 `accounts`、`account_sessions`，关联 `users.id`；凭据不放入业务 State 或同步日志。

| 字段 | 作用 |
| --- | --- |
| `accounts.user_id` | 稳定业务 ID，新用户为随机 ID |
| `username` / `nickname` | 唯一登录标识，忽略 ASCII 大小写，跨字段检查歧义 |
| `password_hash` | 随机盐与 scrypt 派生值，免密时 NULL |
| `passwordless` | 显式模式，数据库约束与派生值保持一致 |
| `preferred_role` | UI 预选角色，不授予权限 |
| `account_sessions.token_hash` | 32 字节随机令牌的 SHA-256；原令牌只进入 Cookie |
| `expires_at` | 30 天固定有效期，访问校验，发会话时清理过期行 |

Cookie 为 `HttpOnly; SameSite=Lax; Path=/`，直接 HTTPS 连接附加 Secure，当前 LAN 使用 HTTP。写请求要求 JSON、`X-Yican-Request: 1`、同源 Origin，不启用跨域接口。Vite 代理保留 Host，使本机开发也能执行同源校验。

密码账号需要旧密码才可改密或开启免密码；免密账号可直接设置密码。改凭据、撤销旧会话、发当前新会话同事务完成；异步密码验证后再次校验凭据版本，避免并发改密后旧登录复活。注册、登录、改密使用轻量内存限频，服务重启后清空，无 Redis 或云服务依赖。

账号与会话重启后保留，仅昵称、头像色等展示资料进入共享状态。免密是主动选择，知道标识者即可进入；密码账号无法从免密入口绕过验证。暂不提供邮箱／短信、密码找回或账号删除。主人可在「厨房与成员管理」交接自己的身份，详见 [厨房管理与菜谱编辑](厨房管理与菜谱编辑.md)。

## 授权与同步

HTTP 命令 actor 来自会话，拒绝冒用；未登录读写状态返回 401，领域规则再次检查厨房权限。API 返回按用户过滤的完整投影，禁止泄漏全局快照或全局增量。

可见范围为长期成员厨房、有效单餐授权及符合条件的本人历史。库存限主厨、邀请限主人、反馈和爱吃限本人，同餐成员共享点菜与评价，登录后可浏览公共菜谱。无变化返回 revision 与服务器时间，有变化返回完整可见投影，支持 ETag；授权随时间到期时，同 revision 也重新投影。

这是面向小规模的实现：复用现有事务和页面状态，增加独立账号模块，避免通用权限平台。将来数据量增长可在此边界内改为按厨房／餐次分页与授权增量，权限继续留在服务端。

## 旧数据接续

不清空旧库、不替换历史 ID。首位注册者可明确勾选接续原 `chen` 主厨或 `lin` 点菜主人，入口仅在本库无账号且原身份存在时显示。首位接续者发出长期邀请，另一位原主人注册时根据选择的常用身份，绑定尚未认领的另一历史主人。保留原成员关系、爱吃、订单、评价和菜谱，展示昵称更新为注册资料。

首次初始化应由原使用者操作；希望保留旧厨房时先接续再注册其他账号。独立注册不接续则获得空白个人空间，不自动分配历史数据。旧厨房缺少 `dinerOwnerId` 时，以旧列表首位长期点菜成员作为原点菜主人并保存，其余是客人。

新库保留入门公共菜谱，不创建测试厨房、订单或账户。浏览器 localStorage 不会自动导入。完整 SQLite 在线备份含账号与会话；旧格式 `db:export-legacy` 只导出业务兼容数据，不能作为账号备份。

## 验证范围

自动测试覆盖注册登录、免密开关、标识冲突、跨站与冒用拒绝、投影隔离、主人竞争、过期邀请、临时授权、改密与会话撤销、失败整体回滚、重启和旧数据接续。界面使用独立库和仅本机浏览器验证。

真实手机键盘与 Wi-Fi 未验证。最小手动检查：手机尺寸注册建厨房，另一账号从邀请加入，应占空缺主人或成为客人；提交一道菜，主厨同步看到；改密后另一会话退回登录，使用新密码后原厨房仍在。真实跨设备检查需使用者决定部署，开发仍只使用 loopback。
