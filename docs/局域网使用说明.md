# 在局域网中使用一餐

## 部署与访问

1. 服务电脑安装 Node.js 24 LTS 或更新版本，部署时手动双击 `start-lan.cmd`，安装缺少的依赖、构建页面，再显式监听 `0.0.0.0:3000`。
2. 保留启动窗口，电脑不休眠。手机与电脑连接同一路由器，访问窗口打印的局域网地址，不使用访客隔离网络。IP 变化后以窗口为准。
3. 首位使用者注册账号、昵称和密码或选择免密码模式，创建厨房。第二位通过长期邀请注册／登录加入。每个厨房主厨与点菜主人各一位，其他成员是客人。
4. 主厨创建餐次、维护菜单与库存，成员提交点菜。页面可见时每 2 秒自动同步，切回页面立即同步。

电脑也应使用局域网地址生成邀请链接，确保手机可打开。`127.0.0.1` 只代表打开链接的当前设备，不能用于跨设备分享。

后续更新双击根目录 `一键更新.cmd`（或 `update-lan.cmd`）。通过 `start-lan.cmd` 运行的服务会在新版预检通过后自动停服、备份及切换，恢复后仍用原地址；其他启动方式的进程不会被结束，准备的新版下次通过部署脚本启动时生效。更新程序和内置内容，保留账号及厨房数据；规则、失败恢复与环境要求见 [一键更新说明](一键更新说明.md)。

**本机开发不要运行部署脚本。** 双击 `start-demo.cmd` 或运行 `npm run dev`，网页与 API 都仅监听 `127.0.0.1`。默认 `npm start` 同样仅限本机；这次开发和验证未开启局域网、未修改防火墙。

## 账号与邀请

- 账号为 3—32 位字母、数字、点、横线或下划线，昵称 1—18 字符，两者不可与其他人的账号或昵称重名。密码 6—128 位。
- 登录可用账号或昵称，只有主动开启免密码的账号才能免密进入。
- 右上角头像或「我的 → 我的账号」可改密码、切换模式、退出。改密或切换模式撤销其他设备全部旧会话。
- 长期邀请 7 天有效，用于邀请主人或客人，主人名额占满后只能成为客人。
- 单餐邀请锁定餐次，只在仍可点菜时接受加入，餐后自动失效；有原订单的来客仍可补评。
- 无有效餐次时只能长期邀请，点菜主人先建厨房也能邀请主厨。
- 旧库首次接续见 [账号与邀请设计](账号与邀请设计.md)。

免密码意味着知道账号或昵称即可进入，仅适用于信任的家人朋友。当前没有邮箱、短信或忘记密码找回。

## 断线与同时操作

保存成功后才清空购物车或关闭编辑面板；断线显示“保存结果尚未确认”并保留输入。恢复后可重试，服务器按请求编号去重。刷新会丢失未提交草稿和内存重试编号，请先检查保存结果。

同时修改库存、订单、厨房名称或菜谱时检查原版本，防止覆盖他人修改。时间和权限在服务端再次验证，餐次按本地时间输入，设备应保持同一时区。账号过期或其他设备改密后，网页回到登录入口。

服务端仅返回当前账号有权查看的厨房和餐次，库存限主厨、邀请限主人、反馈限本人；公共菜谱登录后可浏览。客人无法通过界面或修改请求管理厨房。

## 数据、停止与备份

- 默认 `data/kitchen.sqlite`，运行中可能同时存在 WAL/SHM 文件。账号、会话与业务数据一起持久保存。
- Ctrl+C 或关闭窗口停止，再启动读取原库；正常会话 30 天有效，服务重启不强制退出。
- `backup-lan.cmd` 或 `npm run backup` 生成 `data/backups/kitchen-时间.sqlite`，含账号和业务数据，可在线执行。
- 恢复：停服，将原 `data` 目录改名保留，新建空目录，将备份复制为 `data/kitchen.sqlite` 后启动，不要混用旧 WAL/SHM。
- 同一库只运行一份应用服务，源码和 Git 不包含数据库及备份。

## 连接与配置

手机打不开，先确认电脑可访问、手机同 Wi-Fi、地址与窗口一致。实际部署如需防火墙配置，附带的 `allow-lan.cmd` / `allow-lan.ps1` 仅用于管理员明确放行本地子网 TCP 3000；开发和调试不运行它们。不需要公网端口映射。

生产环境可通过 `YICAN_HOST`、`YICAN_PORT`、`YICAN_DATA_DIR` 配置地址、端口与数据目录。开发脚本固定 API `127.0.0.1:3000`、Vite 本机 5173；独立开发数据只需设置 `YICAN_DATA_DIR`。

本次未验证真实 iOS／Android、Wi-Fi 连通性和防火墙。若决定部署，最小检查是在两台设备分别注册、邀请加入并提交一道菜，另一端应自动显示；修改密码后，另一会话应要求重新登录。开发验证继续仅限本机。
