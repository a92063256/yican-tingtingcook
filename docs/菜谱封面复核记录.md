## 升级与维护

修正文件纳入内置内容版本。已有数据库启动时，公共导入菜谱及带继承标记的私家菜谱若仍使用该菜谱已知的受管理封面，就只更新图片和配图元数据。用户自选的图片或插画保留；不改菜名、用量、步骤、菜单、订单、库存或评价。旧私家版本没有继承标记时，采取保守规则保留其图片，不猜测用户是否手动换过图。

有厨房、订单或私家菜谱的文件数据库，更新前自动备份到数据库同级 `backups/pre-bundled-catalog-*.sqlite`。相同内容版本重复启动不重写。替换 WebP 缺失、字节数或 SHA-256 不符时，校验中止，不先修改数据库。

后续继续换图时，在修正项记录完整来源与许可，提交对应 WebP。将被替换的旧修正图片哈希保留在 `previousImages[recipeId]`，便于已有安装继续跟随修正；原包图片哈希已自动纳入已知旧图。不要直接修改受校验保护的原始 `manifest.json`、Markdown 或许可证。

本次验证：完整 110 项测试、TypeScript 与生产构建；隔离数据库浏览器完成 23 项断言，覆盖本地图片解码、占位、参考标识、私家编辑保存及 320 / 390 / 1440 像素布局，并检查手机截图。已有数据的封面升级、备份可恢复、幂等、自选图保护及损坏图片阻断均有回归测试。

未验证真实手机与 Wi-Fi。最小手动检查：刷新「发现菜谱」，搜索「梅菜扣肉」应看到扣肉照片；「咖喱炒蟹」应为待补充占位；「蒸水蛋」应为带参考标识的蒸蛋图。可用本机浏览器手机模式完成，无需开放局域网。开发与验证始终只监听 `127.0.0.1`。
